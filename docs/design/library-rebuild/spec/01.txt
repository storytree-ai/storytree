  Capability "1 · Project libraries" (capability_5e0362aae607): reported not checked, verified passing; healthy; held by Claude Code 84b4e8a8-ed5a-4efc-b504-bc5a83494f0e: Library refactor step 1: close the picked tree's cycle sets
    About: Each project gets its own library, a separate database on one Postgres server, created on its first open and kept apart from every other. Its tables are set up automatically, and brought up to date by the next open after storytree adds to them; opening a project whose tables are current touches no table. Storytree can list the projects on the server. Nothing written in one project shows up in another, except what a product reads from its factory. (ADR-1243)
    Decisions: founded on "1 · Project libraries: founding book (ADR-0621 D3)" (decision_a821017e746d, ADR-0699).
    Contract "1.1 · `openProject("site")` on a server with no storytree databases creates the project's database and its tables; a project set up before a table changed gains what was added since at its next open." (contract_029ae7c7f781): reported not checked, verified passing; proved by a test criterion: A test can open a named project on an empty server and read that its database and tables now exist, including columns added later.
    Contract "1.2 · Opening the same project again succeeds and changes nothing (no error, no second database, its records are untouched)." (contract_9114d9634c11): reported not checked, verified passing; proved by a test criterion: A test can open a project twice and check no error, no second database, and its records unchanged.
    Contract "1.3 · After opening "site" and "app", `listProjects()` returns exactly `["app", "site"]`. Databases on the server that are not storytree projects are never listed." (contract_aa9cc9f300f2): reported not checked, verified passing; proved by a test criterion: A test can compare the list of projects to exactly the two it opened, with foreign databases left out.
    Contract "1.4 · A record saved in "site" cannot be read from "app"." (contract_908e6b967957): reported not checked, verified passing; proved by a test criterion: A test can save a record in one project and check that a read from the other project finds nothing.
    Contract "1.5 · A project name that is not lower-case letters, digits and single hyphens (1–40 characters, starting with a letter or digit) is refused before anything touches the server, and the error names the rule." (contract_e1281d3d30be): reported not checked, verified passing; proved by a test criterion: A test can pass a malformed project name and see it refused, with the rule named, before any server call.
    Contract "1.6 · `snapshot("site")` returns every record of the project and its whole history, as they stood at one moment, while writes go on." (contract_54daaedc1f9c): reported not checked, verified passing; proved by a test criterion: A test can take a snapshot during concurrent writes and compare it to the records and history at one moment.
    Contract "1.7 · `restore("copy", snapshot)` into a project with no records and no history gives back the same records and the same history, sequence numbers, actors and times included, and the next write continues after them." (contract_cc464355d751): reported not checked, verified passing; proved by a test criterion: A test can restore a snapshot into an empty project and compare records, history, sequence numbers, actors and times.
    Contract "1.8 · Restoring into a project that holds any record or any history is refused, naming the project, and writes nothing." (contract_b7b65435710c): reported not checked, verified passing; proved by a test criterion: A test can restore into a project holding records and see the refusal naming it, with nothing written.
    Contract "1.10 · Opening a project whose tables are current runs no table setup and writes nothing, so an account that may only read its tables (not their owner, no right to create in its schema) opens it and reads its records." (contract_e7f8bb1aa247): reported not checked, verified passing; proved by a test criterion: A test can open a current project as a read-only account and check that no table statement runs and records read.
    Contract "1.11 · Opening a project whose tables are not current, as an account that may not change them (no CREATE on its schema, or not holding the owner's rights over its tables), changes nothing: no table statement runs and no memory is converted. A project set up before opens as its tables stand, reads and writes as the account's grants allow, and warns once per process per project, naming the project, the account and the role owning its database. A project never set up is refused with a ConnectionError (`project-owner`) naming the project and the account and saying that only the role owning its database may set it up. Its owner's next open sets the tables up as before.
" (contract_d017d0b38ff6): reported not checked, verified passing; proved by a test criterion: A test can open a stale project as an account without rights and read the warning, the refusal error and that nothing changed.
    Contract "1.12 · `dropProject(name)` deletes the project's database, with every record and all its history, for every machine using the server; it is listed no more, other projects are untouched, and an unknown project is refused.
