Story "The library" (story_754e87e7d531): reported not checked, verified passing
  Capability "2 · Library transactions" (capability_5a80222c88c4): reported not checked, verified passing; healthy; nobody holds it
    About: The library's only data actions: save a record, fetch it, list records of one type, change only named fields, retire with a reason, and revert. A revert takes a record, retired or not, back to the state one of its own history entries kept, or every record one writer wrote back to its state before that writer's first write, refused where another writer wrote since. Every change is all-or-nothing, and is written first to a permanent, append-only history, so nothing is ever truly erased.
    Decisions: founded on "2 · Library transactions: founding book (ADR-0621 D1)" (decision_59bc36372634, ADR-0700).
    Contract "2.1 · `save` creates a record. Saving the same id again replaces it, and each save appends one history entry." (contract_740f5e8967bb): reported not checked, verified passing; proved by a test criterion: A test can save a record, save it again and count one history entry per save with the record replaced.
    Contract "2.2 · `edit` changes only the fields it names; every other field keeps its stored value." (contract_e3f8c0cd8829): reported not checked, verified passing; proved by a test criterion: A test can edit one field and read back that every other stored field kept its value.
    Contract "2.3 · `edit` merges onto what is stored NOW, not onto a copy the caller read earlier. If two edits of different fields race, both survive." (contract_ba846c24edfe): reported not checked, verified passing; proved by a test criterion: A test can race two edits of different fields and read back that both changes survived.
    Contract "2.4 · `edit` of a missing record returns `null` and creates nothing." (contract_615c0af07ec6): reported not checked, verified passing; proved by a test criterion: A test can edit a missing id and check the call returns null and no record appears.
    Contract "2.5 · `get` of a missing record returns `null` and never throws." (contract_25bd3426ded9): reported not checked, verified passing; proved by a test criterion: A test can see the answer: get of a missing id returns null without throwing.
    Contract "2.6 · `list(type)` returns only that type's current records (none retired), and `[]` when there are none." (contract_4c81d4cad00f): reported not checked, verified passing; proved by a test criterion: A test can list a type and check only live records of that type come back, and an empty list when none.
    Contract "2.7 · `retire(id, reason)` removes the record from `get`/`list`, keeps the reason in the history, and retiring an already-retired or missing record is a harmless no-op." (contract_67c43ed3172b): reported not checked, verified passing; proved by a test criterion: A test can retire a record and see it gone from reads with its reason in history, and repeat retirement harmlessly.
    Contract "2.8 · `history()` returns every change in the order it happened, with strictly increasing sequence numbers. `history({ id })` filters to one record, and `history({ since })` returns only entries after that sequence number." (contract_a0db28a06c20): reported not checked, verified passing; proved by a test criterion: A test can read history and check its order, increasing sequence numbers, and the id and since filters.
    Contract "2.9 · A `validate` check passed to `save`/`edit` sees the merged result. If it throws, nothing is written (no record change and no history entry)." (contract_397234bcaed1): reported not checked, verified passing; proved by a test criterion: A test can pass a validator that throws and check no record change and no history entry were written.
    Contract "2.10 · A write naming an `actor` keeps it in history. A write without one is accepted and its history entry has no actor; an edit or retirement never inherits an earlier write's actor. Refused writes and harmless no-ops add no history entry." (contract_32e02eaefb55): reported not checked, verified passing; proved by a test criterion: A test can write with and without an actor and read which history entries carry one, and that refusals add none.
    Contract "2.11 · Save, edit and retire accept an optional abort signal. If aborted before write admission, including while waiting for the project write lock, they reject without changing records or history. After admission, cancellation does not interrupt the write or undo its history. The in-memory twin applies the same boundary at write entry." (contract_5c0be46eb58a): reported not checked, verified passing; proved by a test criterion: A test can abort writes before and after admission and check whether records and history changed.
    Contract "2.12 · `history` also narrows on the server: `from` (a time) keeps the changes made at or after it, to the millisecond, however the time is written; `types` keeps only changes to records of those types (none for an empty list); `oldest: n` or `newest: n` keeps only the first or last n of what matches, still in order. Filters combine with each other and with `id` and `since`; a malformed one (a limit that is not a whole number above 0, both limits, or a time that is not one) is refused with a RangeError before anything is read." (contract_218ef9384d84): reported passing, verified passing; proved by a test criterion: A test can query history with time, type, limit and combined filters and check the results and range errors.
    Contract "2.13 · Lists narrow on the server by ids and stored field values, take an ordered limit, and project only requested fields on the named schema version, and on each older version named with its own fields; a version not named arrives whole. Memory and Postgres agree." (contract_db98aef75172): reported passing, verified passing; proved by a test criterion: A test can list with id, field, limit and field-selection options and compare memory and Postgres answers.
    Contract "2.14 · `revert(id, to, read)` writes the record back to the state its own history entry `to` kept, whole: changed fields restored, removed ones put back, added ones gone. It is one more `updated` entry whose reason names the entry it reverts to, with its writer; nothing in history is rewritten." (contract_ecb00f4e0533): reported not checked, verified passing; proved by a test criterion: A test can revert a record to an earlier entry and compare its fields and the new history entry naming the target.
    Contract "2.15 · A revert of a retired record to an entry before its retirement brings it back live under its own id, created when it first was, so links to that id reconnect. A retirement entry is not a state to revert to." (contract_c5c823322516): reported not checked, verified passing; proved by a test criterion: A test can retire a record, revert it to an earlier entry, and read it live again under its id and creation date.
    Contract "2.16 · A revert is refused, writing nothing, when the record was written to after the entry the writer read (`read` is not its newest seq), when the entry is not the record's own, or when its validate check throws." (contract_706952adf6f3): reported not checked, verified passing; proved by a test criterion: A test can attempt reverts with a stale read, a foreign entry or a throwing check and see each refused unwritten.
    Contract "2.17 · `history({ actor })` keeps only the changes one writer made, as their entries name them, on the server, combined with the other filters.
" (contract_ae9195f066ae): reported not checked, verified passing; proved by a test criterion: A test can filter history by one writer and check only that writer's entries return, combined with other filters.
    Contract "2.18 · `revertWrites({ of })` writes every record `of` wrote (health left out) back, in one write, to its state before `of`'s first write to it: a changed record to its entry before, a record `of` retired live again, a record `of` made retired. Each is one more entry naming the writer reverted and the entry it goes back to, with its own writer and reason; a record `of` made and retired itself is left alone. It returns what it changed, by id.
" (contract_0fbb4a621010): reported not checked, verified passing; proved by a test criterion: A test can undo one writer's writes and read each record's restored state and the returned list of changes.
    Contract "2.19 · `revertWrites` is refused, writing nothing, when another writer (named or not) wrote to any record `of` wrote after `of`'s first write to it: LaterWriterError names each such record with the first such entry and its writer. A check that throws refuses it whole too.
" (contract_1e5585cb3753): reported not checked, verified passing; proved by a test criterion: A test can have a later writer touch a record and see the undo refused with an error naming record, entry and writer.
    Contract "2.20 · A write made for a writer who had read outside text keeps what it read in its history entry; a write without one carries no mark" (contract_b71efc5e7610): reported not checked, verified passing; proved by a test criterion: A test can write after reading outside text and read the mark on the history entry, and its absence otherwise.
    Contract "2.21 · A library whose history has no place for the outside-text mark yet writes and reads its history as before, leaving the mark off" (contract_40e7dd6453d8): reported not checked, verified passing; proved by a test criterion: A test can write to a library missing the mark column and check history writes and reads still succeed without it.
    Contract "2.22 · Each history entry read back names the account the server saw write it" (contract_d4b54814dc8f): reported not checked, verified passing; proved by a test criterion: A test can read back a history entry and compare its recorded account with the one the server used.
    Contract "2.23 · `history({ actions })` keeps only the changes of those actions (created, updated, retired), on the server, combined with the other filters; none for an empty list, and an action no change has is refused with a RangeError before anything is read." (contract_ba35fab98be9): reported not checked, verified passing; proved by a test criterion: A test can filter history by created, updated or retired and check the results, and see an unknown action refused.
    Contract "2.24 · inOneWrite commits every write its work makes together, or none when the work throws" (contract_05b02e8ff2d9): reported not checked, verified passing; proved by a test criterion: A test can make a throwing unit of work and check none of its writes were committed, or all when it succeeds.
    Contract "2.25 · saveAll saves every record given in one write, each with its history entry in the order given, or none when one is refused" (contract_b33a64099691): reported not checked, verified passing; proved by a test criterion: A test can save a batch and read back each record and its history entry in order, and a batch with one refused record leaves the history unchanged.
    Contract "2.26 · Lists narrow on the server to the records that name an id in a field: a top-level field whose value is that id, or a list field holding it among its members; a field that only mentions it in prose does not count. Memory and Postgres agree." (contract_797f4bf25a5b): reported not checked, verified passing; proved by a test criterion: a list's returned records show it
