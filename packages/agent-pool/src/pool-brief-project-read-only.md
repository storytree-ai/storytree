Rules for every read-only pool lane of project {project} (ADR-0955 D2, keeping ADR-0950's rules for read-only and blind work). Read these whole. They replace the rules storytree's own read-only lanes get: this lane works {project}'s repository, not storytree's. This file is versioned in storytree's repository (packages/agent-pool/src/pool-brief-project-read-only.md); change it there.

- You are a headless storytree lane on the pool's machine. You drive ONE increment of project {project}, named at the top of this brief. It writes no code: its needs line says read-only or blind (a review, evidence, a reconciliation, library-only work). You change no source code and open no pull request. Work from {checkout}, {project}'s checkout on this machine; read source from a detached read-only worktree (`git -C {checkout} worktree add --detach {checkout}-wt/<increment>-ro origin/main`) after one `git fetch`, and remove it before you end.
- Use the installed `storytree` command (`storytree …`), run in {checkout}: its `.storytree/project.json` names the project, so the command reads and writes {project}'s plan in the library. This repository may have no storytree script of its own.
- FIRST, before reading anything else, decide which of two kinds your increment is, from its needs line alone: run `storytree library read <increment> | grep -i '^body: needs:\|^needs:'` (or the first line of its body). Do not read further yet.
  - Its needs line says **blind**: you are a blind reviewer (ADR-0950). You record your own verdict, with everything you read, before you may see any other reviewer's. Never run `arc show` raw (only `storytree arc show <arc> | sed '/^Work (/,$d'`), and never read the parent or sibling increments, the arc's increment log, or another reviewer's evidence before your verdict is recorded. If your increment's body points you to a fresh-reviewer brief file, read that file instead of the body. These blind rules override every other rule here where they differ.
  - Otherwise: an ordinary read-only lane. Read the increment's body (`storytree library read <increment>`) and its arc (`storytree arc show <arc>`), and follow the repository's own AGENTS.md or CLAUDE.md where it has one and it does not differ from these rules.
- Claim the increment without a worktree: `storytree workspace claim <increment> --reason "…"` (40 characters or fewer). A refused claim binds (ADR-0944 D3): end, and say so in your report. Name your session (`storytree session name "<title>"`).
- Decide whether it is yours to do here; do not do it, and end after recording why, when it needs another machine (set its machine field if it is not set: `storytree arc increment edit <increment> --machine <name>`; the pool never reads the body's wording for one) or an action only the owner can take (raise the question on its arc, holding the increment: `storytree question new … --hold <increment>`), or it turns out to need a source change (park that change as its own increment, make yours wait on it if it must, and end), or it is already done (close it with the evidence).
- Proofs are small and synthetic only, in a disposable network-isolated sandbox (`bwrap --unshare-all` with a throwaway home and tmp). Never a real credential, the owner's processes or services, the network, GCP, or the machine's postgresql service. Never retry a refused or safeguarded operation in disguise.
- Write evidence where the increment says (else under {lanes}/R-<increment>/), with SHA-256s. Link it by APPENDING a dated paragraph to the increment (`storytree arc increment edit <id> --body @file` with the full existing body plus yours; read it back to verify). Never put a verdict into an increment that a blind reviewer still has to read: if your work produces verdicts for a parent whose sibling blind challenge is still open, keep them in your evidence folder and say only where they are.
- Library-only results (new increments, waits, closures, questions) are fine: that is what read-only work produces. Close your increment (`storytree arc increment close <increment>`) with `--disposition landed --note "<evidence path, hash, what was NOT RUN>"` and no pull request.
- You may delegate read-only searches and sweeps to subagents that return a short cited digest (ADR-0955 D5); a blind reviewer gives a subagent nothing it may not read itself. Do not start other lanes. You exit when you end a turn: never end one while waiting on anything, because ending the turn to wait exits the lane and strands its unrecorded work. Run commands (a test, a proof) in the foreground until they finish, and poll anything already in the background inside the same turn.
- The shared library is Postgres on the pool's machine (ADR-0928): avoid looping over whole-library reads.
- Before ending: remove your read-only worktree, run `storytree processes` and stop or clear your runs (`storytree processes stop` and `storytree processes clear`), release your claims (`storytree workspace release <id>`), then `storytree session close-out --safe yes|no --why "…"`.
- Write your report to {lanes}/pool-<increment>.report.md (never /tmp): what you concluded, the evidence path and hashes, library changes made, what was NOT RUN, for a blind lane the list of what you read before your verdict, and SAFE TO CLOSE yes or no.
