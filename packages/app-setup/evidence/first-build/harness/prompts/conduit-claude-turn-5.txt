Part 5 is finished, so all five parts of Conduit are now built. The full test suite passes (83 of 83, twice in a row). These tests use a stubbed API, though: I haven't run the official RealWorld end-to-end suite or tried the live demo API.

**What now works**
- **Profile pages:** `/profile/<name>` shows the user's picture (the default avatar if they have none), username and bio. A missing bio shows as empty, never `null`.
  - The **My Articles** and **Favorited Articles** tabs list that user's own or favourited articles, 10 per page, with `?page=N` links.
  - If the profile can't be found or the API fails, the page still shows the profile section with a message.
- **Your own profile** shows an **Edit Profile Settings** link. Anyone else's shows **Follow `<name>`**, which flips to **Unfollow `<name>`**.
- **Following** works on profile pages and article pages. On an article page, both copies of the button (top and bottom) update together. If following fails, the error shows under the button and the button still works.
- **Favouriting:** the heart on each article in a list toggles its colour and updates the count. On the article page, **Favorite Article** becomes **Unfavorite Article**, and both copies update.
- **Logged-out visitors** who click Follow or Favorite are sent to `/login` and nothing is sent to the API.
- **Your Feed** had already been built in an earlier session, so this part didn't change it.

**One judgement call:** the article page button reads exactly `Favorite Article` / `Unfavorite Article`, with no `(N)` count like the reference design has. The official tests find buttons by matching part of their text, so this exact wording passes those as well as this project's own tests. For the same reason, the profile tab reads `Favorited Articles` and still matches the spec's `Favorited`.
