**The cause:** the `.user-info` box was drawn as soon as the page opened and only filled in later. While the profile was loading, its `p` held "Loading profile...", which is what the null-bio and clear-bio tests read. When loading failed, the error message went inside `.user-info` too, so `.profile-page, .user-info` matched two elements.

**The fix** (`public/profile.js`):
- `.profile-page` now holds a slot above the article tabs instead of a ready-made `.user-info`.
- While loading, the slot shows "Loading profile..." outside `.user-info`.
- When the profile loads, the slot is replaced with the full `.user-info` box.
- When loading fails, the slot shows "Profile not found." for a 404 or "Could not load this profile. Please try again." for anything else. There is no `.user-info`.
