```js
cy.createTodo(TODO_ITEM_ONE).as('firstTodo')

```

It saves references to the two `<li>` items it created, reloads the page, then checks those same saved items again. A reload replaces the whole page, so the old items are gone no matter what the app does. Older Cypress versions looked the items up again automatically. Cypress 12 and later only do that for aliases built from lookup commands like `cy.get`, and `createTodo` is a custom command that adds a todo, so the test fails with exactly the error you saw. Our earlier fix keeps list items in place while the page stays loaded, but nothing can carry them across a reload. A fix in the suite would look the items up again after the reload, e.g. `cy.get('.todo-list li').eq(0)`.

The app's saving and reloading does work: the local test in `test/tests.html` checks that todos come back after a reload, and another checks that completed state is saved. I didn't re-run the local tests this session because no code changed.
