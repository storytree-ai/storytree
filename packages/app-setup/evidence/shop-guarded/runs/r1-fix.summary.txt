I've fixed the locked-user test, and the fix is merged (pull request #2, after both checks passed). Parts 2ÔÇô4 can start now.

**What was wrong:** line 27 checks for the error message straight after clicking Login, without waiting. On saucedemo.com the error appears within that same click. On our shop, a refused sign-in went to the server and reloaded the page to show the error. If the test looked before the reload finished, it saw the old page with no error and failed. That's why it failed only some of the time.

**The fix:** the sign-in page now checks the details in the browser as you click. A refused sign-in shows its error straight away and never leaves the page, as on saucedemo. A correct sign-in still goes to the server, which checks it again with the same rules and signs you in.

**How I checked it:**
- I couldn't make the old version fail here: Edge passed it every time, even with the server slowed down on purpose. So I haven't watched the failure go away. What I can show is that the gap it fell into no longer exists.
