**What now works on Products:**
- A search box (`[data-test="search"]`) filters the list on every keystroke. It matches product names and descriptions and ignores case, so "BACKPACK" leaves only the Backpack and "streamlined" finds it through its description.
- The address keeps the search (`/inventory.html?q=backpack`). Opening or reloading that address shows the box filled in and the list already filtered. Clearing the box removes `?q=` and brings all six products back.
- When nothing matches, the page shows `[data-test="no-results"]` "No products match ÔÇ£zebraÔÇØ." and contains no `.inventory_item`.
- Sorting (`az`, `za`, `lohi`, `hilo`) works on the filtered list. Products that come back as the search widens return in the chosen order.

I also drove it in headless Edge, and it behaved the same there as in the tests. That run caught one case worth knowing about: after reloading a filtered address and widening the search, the products that come back now have working Add to cart buttons. To make that work I changed the cart-button script in the same package, and I added a little styling for the box and the no-results message.

**One design choice:** for a filtered address, the server keeps the products that don't match in a hidden `<template>`. That keeps them out of the page itself, so a browser-based test sees no `.inventory_item` for them. A test that searches the raw HTML text would still find them, though. If your own tests read raw HTML, tell me and I'll load them a different way.
