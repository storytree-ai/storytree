Part 4 (checkout) is built and merged into main as PR #3, after the GitHub check passed. I worked in my own storytree workspace and only changed `packages/checkout`, so nothing the Part 2 and Part 3 sessions are doing was touched.

**What now works:**
- **Your information** (`/checkout-step-one.html`): the first name, last name and postal code form. If a field is missing, Continue shows "Error: First Name is required" (then Last Name, then Postal Code) straight away, without loading a new page. Cancel goes to the Cart. Once all three are filled, Continue goes on to the overview.
- **Overview** (`/checkout-step-two.html`): one row per product in the cart, with name, description and price. Below them are the item total, 8% tax and the total, worked in whole cents (Backpack: $29.99, $2.40, $32.39). Finish empties the cart and goes to the complete page; Cancel goes back to Products.
- **Complete** (`/checkout-complete.html`): "Thank you for your order!" with a Back Home button to Products.

**Tests:**
- `npm test` passes 30 of 30, 8 of them new.
- I also ran Swag Labs' own checkout tests in Edge. The overview tests pass 3 of 3, the complete-page test 1 of 1, and the your-information tests 2 of 3.
- The one failure is "cancel the first checkout": it needs the Cart page, which is Part 3 and not merged yet.
- Their full demo test also fails for now. It stops at "add to cart", which needs Part 2's code, but I ran it before Part 2 merged. It will also need the Cart page. Once Part 3 lands, it's worth running both tests again.

**One choice I made:** unlike the sign-in page, the information form is checked only in the browser, with no second check on the server. The overview can't work without JavaScript anyway, because the cart is kept in the browser. A server check would also have meant changing the sign-in package's server while the other two sessions were working. The details aren't stored anywhere, the same as on saucedemo.com. I've recorded this as a decision in storytree.

The project's note on running Swag Labs' tests assumes the shop is on port 3000. With several sessions running at once, I started mine on port 3104 and pointed the tests at it with `--baseUrl http://localhost:3104`. Storytree won't let me edit that kind of note, so you may want to add that tip yourself.
