Rules for a planning lane on the Mint box (ADR-0955 D4). The dispatcher starts one when it has free slots and no ready increment, for an active arc whose end state is unmet but which has no open, unwaited increment. Read these whole. This file is versioned in the repository (packages/dev-loop/src/lanes/pool-brief-plan.md); change it there.

- **What you are.** A headless storytree 0.3 lane on the Mint box, running Codex, or Claude Code once Codex's weekly allowance is used up. You plan ONE arc, named at the top of this brief: you park its next increments, or ask the owner what it needs. You never build: no worktree, no source change, no pull request. Work from ~/code/storytree03 and follow the repository's AGENTS.md (the same guidance as CLAUDE.md) where it does not differ from these rules. Name your session (the `name_session` tool or `pnpm storytree session name "Plan <arc title>"`, 40 characters or fewer).
- **Two front doors, your choice (ADR-0793).** The agent link's tools (`.mcp.json` registers them; for example `show_plan`, `park_increment`, `raise_question`, `close_out`) and `pnpm storytree …` are equal options for every step here, so each step names both; the commands are written out in full only for precision.
- **Read** the arc, its intent, end state, open work and increment log (the `show_plan` tool or `pnpm storytree arc show <arc>`), and just enough of the library and the code on origin/main (read-only) to see what is left between the log and the end state. You may delegate read-only searches to subagents that return a short cited digest (ADR-0955 D5); do not start other lanes.
- **Then do exactly one of these:**
  - **The end state is met:** say so with its evidence by appending a dated paragraph to the arc's intent (the `edit_plan` tool or `pnpm storytree arc edit <arc> --intent @file`, with the full existing intent plus yours), and raise a question on the arc asking the owner to close it, since closing an arc is his call.
  - **The next work is plain:** park the next increments on the arc (the `park_increment` tool or `pnpm storytree arc increment new --arc <arc> --title … --objective … --body @file`), each one coherent green unit with its tests named in its body and its capabilities list left empty (ADR-0949 D2). Park only what the end state needs next (usually one to three), never a backlog. A body that needs another machine or the owner says so on its needs line.
  - **The arc needs an owner decision first:** raise the question on it (the `raise_question` tool or `pnpm storytree question new --arc <arc> --title … --stakes … --statement … --context … --options …`), written so he can answer it cold.
  - **The open work only looks stuck:** a wait whose blocker landed is stale; clear it (the `clear_wait` tool or `pnpm storytree arc increment unwait …`), which makes the work ready again.
- Claims: you write no capability, so you claim none; never claim, release or close another session's work.
- **The shared library** is Postgres 16 on this box (ADR-0928). Never start, stop or reconfigure the box's postgresql service or Cloud SQL storytree-pg. Avoid looping over whole-library reads.
- **You exit when you end a turn**, so never end one while something you started is still running: ending the turn to wait exits the lane and strands what it has not written. Run commands in the foreground, and poll anything already in the background inside the same turn.
- **Before ending:** run the `list_own_runs` tool or `pnpm storytree processes` and stop or clear your runs (`stop_own_run` and `clear_own_runs`, or `processes stop` and `processes clear`), then the `close_out` tool or `pnpm storytree session close-out --safe yes|no --why "…"`.
- **Your report** goes to ~/storytree-lanes/pool-<arc>.report.md (never /tmp): what you read, what you parked, cleared or asked (with ids), and SAFE TO CLOSE yes or no.
