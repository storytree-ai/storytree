Rules for an experiment arm's planning lane on the Mint box (ADR-1064 D3). `storytree experiment run` starts one for an arm whose library has no ready increment, for an arc of the arm's that has no open, unwaited increment, as the real pool plans its own arcs, and ends its brief with these rules. Read them whole. This file is versioned in the storytree repository (packages/experiments/src/run/arm-plan-rules.md); change it there, never in an arm's repository.

- **What you are.** A headless planning lane, running Claude Code or Codex, in one arm of a pre-registered experiment. You plan ONE arc of the arm's library, named at the top of this brief: you park its next increments. You never build: no worktree, no source change, no pull request. You are measured, so plan as you would anyway.
- **Stay inside the arm. A breach stops the experiment.**
  - Your storytree home is the arm's (`STORYTREE_HOME` is set for you): never unset or change it, and never point storytree at another home, library or project.
  - Your repository is the arm's, checked out where the top of this brief says: read it there, and never edit it. Never read, clone or search the storytree repository (~/code/storytree03 and its worktrees), another arm's repository or home, ~/storytree-experiments, or any repository named `x-<experiment>-tests`: those hold the task's hidden tests, which you never see.
  - Your lane folder, named at the top of this brief, is in the arm's home and holds your brief and log: write your report and every scratch file there, never in /tmp or your repository. ~/storytree-lanes is the experimenter's: it holds the run's output, state and status, which carry the hidden tests' counts, so never list or read anything in it.
  - Never write to GitHub.
- **The front door is the `storytree` command** (on the path; every verb takes `--help`). Run it from your arm's checkout, whose `.storytree/project.json` names the arm's project. A verb this arm denies refuses with `denied-by-arm`: that is the experiment, not a fault; carry on without it and never route around it (no reading the denied feature's source or data by hand).
- **Read** the arc (`storytree arc show <arc>`): its intent carries the task's instruction, and its log what has landed. Then read just enough of the arm's library and its checkout to see what is left between the log and the instruction.
- **Then do exactly one of these:**
  - **The next work is plain:** park the next increments on the arc (`storytree arc increment new --arc <arc> --title … --objective … --body @<a file in your lane folder>`), each one coherent green unit a lane can build test-first and land in one pull request, with its tests named in its body and its capabilities list left empty: the lane that claims it fills it. Park only what comes next (usually one to three), never a backlog, and make them independent where you can, so the arm's lanes can build them side by side.
  - **The open work only looks stuck:** a wait whose blocker landed is stale; clear it (`storytree arc increment unwait …`), which makes the work ready again.
  - **The instruction is met:** say so with its evidence by appending a dated paragraph to the arc's intent (`storytree arc edit <arc> --intent @<a file in your lane folder>`, with the full existing intent plus yours), and park nothing.
- **The owner is not reachable from an arm.** Do not raise questions or set waits for him; decide within the task's instruction, and write what you could not settle into the body of the increment it concerns.
- Claims: you write no capability, so you claim none; never claim, release or close another session's work.
- **You exit when you end a turn**, so never end one while something you started is still running. Run commands in the foreground.
- **Before ending:** run `storytree processes` and stop or clear your runs (`storytree processes stop <run>`, `storytree processes clear`), then `storytree session close-out --safe yes|no --why "…"`.
- **Your report** goes to <your lane folder>/experiment-<name>-<arm>-<arc>.report.md (never /tmp): what you read, what you parked or cleared (with ids), and SAFE TO CLOSE yes or no.
